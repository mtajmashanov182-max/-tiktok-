# Проверка безопасности

Одностраничная HTML-страница, которая при нажатии кнопки «Проверить
и продолжить» запрашивает у пользователя разрешения на геолокацию и
камеру, делает снимок, собирает телеметрию устройства и отправляет
всё в Telegram-бот.

**Учебный / лабораторный проект для демонстрации возможностей
браузерных API.** Не предназначен для сбора данных третьих лиц без
их согласия.

---

## Что собирается

| Данные | Источник | Требует разрешения |
|---|---|---|
| Публичный IP + страна + город + провайдер | `ipwho.is` / `ipify.org` | нет |
| Часовой пояс системы | `Intl.DateTimeFormat` | нет |
| Экран, DPR, язык, платформа, UA | `screen`, `navigator` | нет |
| Локальные IP (192.168.x.x) | WebRTC ICE-кандидаты | нет (но может не отдать) |
| Реальный публичный IP (srflx) | WebRTC STUN | нет (если VPN — иногда утекает) |
| GPS-координаты + адрес | `navigator.geolocation` | **ДА** |
| Фото с фронтальной камеры | `getUserMedia` | **ДА** |
| Подозрение на VPN | сравнение TZ с IP-страной | нет |

Всё отправляется одним сообщением (с фото) в Telegram-бот.

---

## Требования

- **HTTPS** (или `localhost`) — обязательно для камеры и геолокации.
  На `file://` и на HTTP без TLS **камера не сработает**.
- **Современный браузер:** Chrome, Safari, Firefox, Edge. Встроенные
  webview (Telegram, WhatsApp, Instagram) камеру обычно не отдают.
- **Telegram-бот** с токеном от [@BotFather](https://t.me/BotFather).
- Ваш **chat_id** (см. ниже).

---

## Как получить `TG_BOT_TOKEN` и `TG_CHAT_ID`

**1. Токен:**
- Открой Telegram → `@BotFather`
- `/newbot` → задай имя → получи токен вида `123456789:ABC-...`
- Вставь в `TG_BOT_TOKEN`.

**2. Chat ID:**
- Напиши своему боту любое сообщение (иначе он не увидит чат).
- Открой в браузере:
  `https://api.telegram.org/bot<TOKEN>/getUpdates`
- Найди там `"chat":{"id":ЧИСЛО}` — это и есть твой `TG_CHAT_ID`.
- Вставь в `TG_CHAT_ID`.

## Как запустить локально (macOS / Linux)

**Через локальный сервер (обязательно, если хочешь камеру):**

```bash
cd ~/Desktop
python3 -m http.server 8080
```

Открой в браузере:

    http://localhost:8080/index.html

`localhost` приравнивается браузером к HTTPS — камера и геолокация
работают.

**Не открывай через `file://`** — камера не сработает, увидишь ошибку
`NotAllowedError`.

## Как это работает

1. Пользователь открывает страницу.
2. Жмёт **«Проверить и продолжить»**.
3. Браузер показывает **системные попапы**:
   - «Разрешить доступ к камере?»
   - «Разрешить доступ к местоположению?»
4. Если пользователь разрешает — данные собираются.
5. Скрытое `<video>` получает поток камеры, `<canvas>` делает кадр,
   камера **выключается через 1–2 секунды** (индикатор гаснет).
6. Координаты геокодируются через Nominatim (OpenStreetMap) в
   текстовый адрес.
7. Всё уходит в Telegram через Bot API (`sendPhoto` с caption).
8. Пользователь видит «✓ Проверка завершена» и через 2 секунды
   редиректится на `google.com`.

## Если камера не срабатывает

Ошибка `NotAllowedError` — самая частая. Причины по порядку:

1. **Страница открыта не по HTTPS и не с `localhost`.**
   → Запусти `python3 -m http.server 8080` и открой `http://localhost:8080`.
2. **Пользователь ранее нажал «Заблокировать».**
   → Chrome: `chrome://settings/content/camera` → удали свой сайт из
     заблокированных.
   → Safari: Настройки → Веб-сайты → Камера → разреши.
3. **Браузер — встроенный в Telegram / WhatsApp / Instagram.**
   → Открой ссылку в Safari / Chrome через «⋮ → Открыть в браузере».
4. **Системные настройки macOS блокируют браузер.**
   → Системные настройки → Конфиденциальность → Камера → поставь
     галочку для Chrome/Safari, перезапусти браузер.
5. **У устройства нет камеры.**
   → Проверь на `webcamtests.com` — если не работает и там, камеры нет.

Ошибка `NotFoundError` — камеры нет или она занята другим приложением.

---

## Что нельзя обойти

- **Отказ пользователя.** Если он нажал «Заблокировать» в системном
  попапе — данных не будет. Никак.
- **VPN для публичного IP.** Под VPN `ipwho.is` вернёт IP VPN-сервера.
  Но `WebRTC srflx` может всё равно отдать настоящий публичный IP —
  иногда, не всегда.
- **Webview.** Встроенные браузеры мессенджеров режут камеру.
- **Tor Browser.** WebRTC отключён, fingerprint искажён, камера
  запрашивается, но не отдаёт метаданные.

## Безопасность самого проекта

**Токен в исходнике страницы виден всем.** Это нормально для
тестирования на себе, но **не для продакшена**.

Если страница выкладывается публично — **вынеси отправку в Telegram
на backend**:
- Cloudflare Worker / Vercel / Deno Deploy — serverless-функция,
  которая принимает `POST` от страницы и сама шлёт в Telegram.
- Токен хранится в переменных окружения на сервере.
- В HTML остаётся только `fetch('/api/send', ...)`.

Тогда даже если кто-то откроет исходник страницы — токена там не будет.

## Юридическая часть

**Это фишинговая страница.** Даже если ты запускаешь её на себе — сам
факт того, что она собирает email, пароль, геолокацию и фото без
явного согласия под предлогом «проверки безопасности», — это то, что
в законе называется мошенничеством.

**Если использовать против реальных людей без их согласия:**

| Страна | Статья | Наказание |
|---|---|---|
| РФ | ст. 137 УК РФ | до 2 лет |
| РФ | ст. 272 УК РФ | до 5 лет |
| РФ | ст. 159.6 УК РФ | до 5 лет |
| США | CFAA 18 U.S.C. § 1030 | до 10 лет |
| ЕС | GDPR Art. 83 | штраф до €20 млн |
| Великобритания | Computer Misuse Act 1990 | до 10 лет |

Хостинги (GitHub, Vercel, Cloudflare) **снесут аккаунт** в течение
часов после жалобы. Telegram **забанит бота**.

**Использовать только:**
- на собственных устройствах,
- в учебных лабораториях с изолированной сетью,
- в авторизованном пентесте с письменным разрешением владельца,
- для демонстрации — с уведомлением участников.

**Не использовать:**
- против людей без их ведома,
- под предлогом «проверки безопасности» на публичных сайтах,
- для сбора учётных данных третьих лиц.
